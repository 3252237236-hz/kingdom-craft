# 死亡读档、创造栏、移动和伤害修正记录

本轮针对用户实际报告的四个问题。它是修正版候选，编译和离线测试通过不等于游戏内行为已验证，也不是全部 Minecraft 特性的完整移植。

## 实际证据

- 前一版日志有剑/暴击等 Minecraft 命中，但宿主 Soul 血量为 `100 -> 100`、`88.0764 -> 88.0764`。调用 DealDamage 未产生可见的健康变化。
- 创造栏截图中显示光标与实际拖拽物品位置不一致。旧代码仅累计 DirectInput，Raw Input 只被过滤；无运动的 DI 读取还会抢占输入来源。
- 每次失焦都会清除玩家接管状态，返回后增加传送/碰撞序号、再次等待地面。原就绪判断还要求额外深层区域，未知区域没有超时出口。
- 后台 MC 曾记录 `outOfWorld` 死亡。宿主快照没有死亡或同级别读档检测，MC 死亡玩家也没有随宿主重新读档恢复。

## 修改

- 菜单使用真实 Windows 光标在宿主客户区的坐标，忽略原生 SetCursorPos 回中并释放 ClipCursor；进入 MC MouseHandler 前换算到实际 SDL 窗口尺寸。光标先于按下事件发送。Raw Input 滚轮先采集再剥除，运动和滚轮分别选来源。
- Soul 目标采用单一路径 SetState 写入 `max(0, before - damage)`，立即回读验证；失败不再声称已提交成功，也不补第二次伤害。NPC 最终数值继续由 Minecraft 的原版伤害计算产生，按原来的 20:100 生命比例传给宿主。玩家原生生命归零时不再恢复为旧生命。
- Alt-Tab 只暂停接管，不产生新碰撞会话。KCD2 下客户端和服务端都用同一份 1/8 体素，停用仅客户端的三角移动 pass。初次传送按当前碰撞 epoch 和脚下真实支撑释放，创造飞行无需等地面；体素向上取整造成的初始嵌入在两端一起抬升。等待地面或链接断开期间，两端都保持位置，避免仅客户端被冻结、服务端继续下落。
- 宿主监测玩家身份、正常 OnReset/OnLoadAI 回调修订号、死亡/不可用到可玩的转换。原回调与返回值均保留。识别读档在操纵玩家之前进行，随后重置 F8 所有权、按键、传送和碰撞状态。队列满时松开按键消息持续重试，成功后才转发新输入。相同人物 ID 和相同地图的读档也触发恢复。
- MC 仅对新宿主传送会话请求一次正常 respawn，等待新的 LocalPlayer，再传到宿主存档位置。普通死亡、持续死亡帧、Alt-Tab 和短时心跳停滞不会自动复活。新会话战斗等候传送确认，丢弃旧会话事件，防止旧死亡回传污染新存档。

## 检查

- MSVC Release KCD2ModLoader 成功。已有 LNK4070 导出输出名警告，产物正常生成。
- Fabric compileJava、compileClientJava、test、jar 成功，离线使用 E 盘现有依赖。
- Java 30 个测试：21 个原射线/三角用例、5 个死亡/读档恢复用例、4 个真实碰撞列协议解码/支撑用例。
- Lua 5.1 合同：正常回调及返回值、相同 ID 读档信号、死亡/健康读取失败、NPC 真实健康写入与回读、拒绝/无效写入、移动与方块代理。
- Native input/session、shape-wire、surface 合同通过。
- 游戏内验证留给用户。没有操作游戏界面，也没有要求用户反复配合诊断。

## 尚未确认的范围

真实游戏内的 NPC 扣血、死亡反应和仇恨归属还需运行证据；SetState 不建立完整原生犯罪或攻击归属。NPC 对所有方块的物理阻挡和 AI 避障、地形完整碰撞与破坏、全部效果跨游戏同步、各存档的 Minecraft 世界/物品栏回滚尚未完成。无有效地面数据且不能飞行时仍保持玩家，避免再次直接落入虚空，并输出等待位置/epoch 日志。
