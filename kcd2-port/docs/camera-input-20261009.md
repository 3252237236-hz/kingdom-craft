# 光标、相机稳定性和第三人称修正版

本轮根据用户反馈继续修改现有移植，不替换已有位移尺度、深度遮挡、投影、场景采样和战斗实现。用户确认 NPC 可以被打死，因此死亡逻辑本轮未改；这属于用户反馈，不等同本轮原生战斗验收。

## 操作

从 Steam 正常启动游戏、载入存档。Minecraft 控制生效后，F5 按原版顺序切换第一人称、后第三人称和前第三人称。左右键、移动、滚轮和物品栏保留 Minecraft 操作。F8 交回原生控制会恢复原生相机。

## 修改

- 光标坐标先从 Windows 客户区换算到游戏渲染尺寸，再转换到 Minecraft 窗口和 GUI 尺寸。合成光标使用坐标来源的宽高，不再将 1920×1080 坐标直接除以 1280×720 backbuffer；像素中心换算也统一。
- 接入可协商的 Minecraft 原版相机控制。确认客户端能力及 `Game.SetViewCameraByAngles`、`Game.ResetToNormalCamera` 可用后，Minecraft 原版鼠标、位置插值和 F5 相机负责视角，原生相机跟随实际渲染相机位置。原生玩家仍同步脚坐标，保留 NPC 交互身份。
- 前第三人称传输实际相机角度，角色移动/攻击角度单独保留。20 Hz 原始物理状态和插值渲染状态仍保留。原生每个 tick 只发布一次最终相机，不再前后发布两个不同视点。
- 原生相对鼠标输入由一条来源传输，过滤原生视角重复响应和隐藏 SDL 窗口的额外输入；队列满时重试鼠标运动。既有 SDL 抓取旁路保留，隐藏窗口使用虚拟焦点。
- 第三人称保留原版相机缩距，使用既有场景碰撞桥接。放置地面射线使用角色眼睛和瞄准角度，前第三人称不会把放置方向反转。
- 相机只接受当前 teleportAck、有效世界、存活状态和新鲜帧；切回原生输入、失焦、断线、死亡/读档时恢复相机。垂直朝上/朝下不会因水平向量为零而触发新会话。
- v11 结构大小和偏移不变。新增协商 flags；在 `MC_CAMERA_FRAME` 下，原有保留字 0x4C、0xBC 分别传输真实渲染相机 yaw、pitch。未协商时仍使用原宿主相机路径。

## 验证边界

候选、构建、隔离存档和备份均在 E 盘。实际 transformed Minecraft 隔离运行检查覆盖前后 F5、两米位移、Minecraft 墙和原生采样墙缩距、光标缩放、隐藏窗口事件抑制及输入单次消费。原生 Lua 合约覆盖坐标和角度参数、API 缺失回退、相机恢复及第三人称放置射线。安装器同时替换 addon、DLL、JAR、实际运行的 classes/resources/src，并进行备份及回滚验证。

构建通过和隔离运行不证明 KCD2 存档内的第三人称、抖动消失或完整移植已完成。原生相机 API 在游戏中的实际执行、Steve 与原生场景遮挡、NPC 战斗回归及用户存档体验仍需实际运行确认。完整移植的其他缺口继续记录在 completion-requirements.md。
