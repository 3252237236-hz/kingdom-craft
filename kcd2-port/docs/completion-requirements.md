# 完整移植验收范围

目标保持为用户要求的完整、可玩移植：将所提供 SkyCraft 的 Minecraft 玩法接入天国拯救 2，并让两个世界遵循彼此的空间、物品、攻击和实体规则。此文件记录范围与证据要求，不把成功定义缩减到已有 demo。

| 要求 | 必须有的证据 | 当前缺口 |
| --- | --- | --- |
| 完整 Minecraft 客户端及原版机制 | 实际运行中覆盖方块、物品、合成、附魔、药水、弓剑、投射物、红石、生物、交通、飞行和维度 | 客户端本体存在；跨引擎效果及维度融合未全部验证 |
| 游戏内安装和正常启动 | 正式启动器加载已验证 DLL、JAR、classes、shader；玩家存档和配置保留 | 本机已安装，仍有实际游戏验证缺口 |
| 原生地面建造及共享碰撞 | 在地面、斜坡、门、墙、家具上放置与破坏；玩家、NPC、生物和物体都遵守同一形状 | 附近场景仍是采样近似，完整网格与动态刚体未统一 |
| 相机、尺度、接地和遮挡 | KCD2 存档中实际两米走动、旋转、前后遮挡、透明物体、粒子、读档 | 隔离相机和合成检查通过；原生距离未测量 |
| Steve 和原版 Minecraft 操作 | 左右键、视角、创造物品栏鼠标、移动、死亡读档恢复；无原人物动作重叠 | 已有修复需要完整存档场景回归 |
| Minecraft 攻击的伤害与反馈 | 普通/跳劈/附魔剑、弓箭、其他投射物打中原生 NPC，正确减伤、击退、死亡和命中反馈 | 已修正 Soul WUID 与 EntityId 混用；原生死亡和识别未确认 |
| 原生武器和盾牌碰撞 | 按实际姿态拦截，伤害和两边命中/格挡/投射物反馈一致 | 已有包围盒预判、单次伤害提交和 MC 拦截反馈；缺乏完整网格、原生反馈及存档实测 |
| 双向生物战斗 | MC 生物有独立原生攻击者身份；NPC 看见、锁定、反击真实 MC 生物；伤害双向回传 | 缺少原生 MC 生物角色代理与反向受伤链路 |
| 原生玩家/NPC 装备与 MC 物品特性 | 护甲、武器、盾牌及原生状态与 MC 物品规则相互作用 | 装备映射和原生物品交互不完整 |
| 环境、流体与物理 | 水/岩浆绕原生几何流动；火、爆炸、活塞、重力、游泳、蛛网等影响两边实体 | 部分环境已接入；完整垂直物理和动态物体未统一 |
| 世界破坏与材料 | 镐、爆炸、火等能影响原生对象，正确改变碰撞、遮挡、AI 与掉落 | 原生网格编辑、对象破坏与材料掉落缺失 |
| 保存、读档和会话安全 | 玩家两边状态一致，旧包不影响新存档；生物代理清理，无重复伤害或永久移动锁 | 攻击确认覆盖 epoch、宿主 generation 和单次提交；完整存档与生物生命周期未验证 |
| 发布源码和证据 | GitHub 源码可构建，指纹匹配安装；不发布游戏本体、提取资源、账号或存档 | 已有私有仓库；每轮继续更新并保留验证范围 |

完成必须覆盖这些要求，并在实际 KCD2 存档中验证。单元测试、合成宿主包或独立 Minecraft 运行不能证明完整移植已完成。未验证的项目仍是未完成项。
